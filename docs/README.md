# مرجع مستندات هم‌خرید

تاریخ بازبینی: ۲۰۲۶-۱۰-۲۸ — گیت‌های M3 در Chromium/Firefox/WebKit، هرکدام ۱۸/۱۸، روی stack جاری و حداقل بررسی شده‌اند. `composer run test:all` سبز است (PHPCS 28/28، PHPUnit 8/8 با 13 assertion و تمام integrationها). QA-124 reactivation و QA-206 multi-embed subset پاس شدند؛ Narrator را کاربر تأیید کرد. SiteOrigin 2.38.0 در مسیر محدود Classic Page Builder/Text widget، با Code→Visual، ذخیره، reload و render پاس شد. در retry تازه با ZIP رسمی Elementor 4.3.5، autoload بدون shim سالم بود؛ دو REST endpoint به‌علت چاپ deprecation در PHP 8.4.1 JSON نامعتبر دادند و در اجرای `display_errors=Off` نیز editor تا ۶۰ ثانیه آماده نشد؛ save/render تأیید نشد. Elementor clean UI، SiteOrigin Gutenberg Layout Block authoring و Elementor Pro Theme Builder (به تصمیم کاربر) تأیید نشده‌اند. Tab traversal در WebKit ادعا نمی‌شود. اصلاح `.mo` برای وردپرس حداقل در گزارش ثبت شده است. M3 و lifecycle محلی M4 در دامنهٔ مستندشده بسته‌اند؛ ZIP فقط در مسیر QA محلی آماده شده و ارسال یا انتشار عمومی انجام نشده است. ZIP SHA-256 `7f4868b8bd54fd772d4bbf5fb8c5ef6044b4c028baf8c9de400c270dc62f884b`. گیت E-15 فقط در محدودهٔ محلی تأییدشده است و SLA عمومی نیست.

این صفحه نقطه شروع و فهرست مرجع توسعه است. اسناد موجود شامل PRD مصوب، معماری، UX، دفتر تصمیم‌ها، roadmap، راهنمای توسعه و QA هستند. کد، target design و نتایج محیط QA شواهد جدا دارند؛ وضعیت جاری و موارد باز را از جدول وضعیت و گزارش QA بخوانید.

## قواعد خواندن و نگهداری

- «مشاهده‌شده در کد» با «آزموده در محیط واقعی» متفاوت است. رفتار هدفِ تأییدشده نیز تا اجرای پلن، قابلیت موجود نیست.
- PRD مالک چرایی و پذیرش است؛ معماری مالک قرارداد فعلی؛ دفتر تصمیم‌ها مالک علت و وضعیت تصمیم؛ برنامه توسعه مالک ترتیب و وضعیت شواهد است. اطلاعات را در چند فایل کپی نکنید.
- هر تغییر عملکردی آینده باید FR/NFR مرتبط، تست، قرارداد معماری و ردیف وضعیت مربوط را در همان تغییر هماهنگ کند؛ فقط اسناد متأثر به‌روزرسانی شوند.
- نتیجه QA با تاریخ، نسخه کد و تغییرات محلی، محیط، فرمان، نتیجه و شاهد ثبت شود. صرف وجود تست یا تیک‌زدن task، اثبات عبور gate نیست.
- اگر کد با هدف محصول اختلاف دارد، هر دو را با برچسب صحیح ثبت کنید؛ کد رفتار فعلی را تعیین می‌کند و PRD رفتار مطلوب را، نه اینکه یکی را بی‌صدا جای دیگری بنشانیم.
- تصمیم مهم باز در [دفتر تصمیم‌ها](decisions-fa.md) ثبت می‌شود. فرضیه بدون پاسخ کاربر «تأییدشده» نشود.
- اجرای جاری شامل پیاده‌سازی و QA محلی مجاز تا آماده‌سازی ZIP پایلوت است. به داده یا هاست واقعی دست زده نشده و انتشار، استقرار یا ارسال بیرونی بدون مجوز انجام نمی‌شود.
- E2Eهای M3 روی سه engine در stack جاری و حداقل، QA-114/124/206 و builder probes در [گزارش QA پایلوت](pilot-qa-fa.md) ثبت شده‌اند. QA-114 برای مسیر SiteOrigin Classic Page Builder از Code→Visual تا ذخیره/بازخوانی/render بسته شد. Elementor clean/default با ZIP رسمی و بدون shim فعال شد و autoload سالم بود، اما REST deprecationهای PHP 8.4.1 را به JSON افزود؛ در variant با `display_errors=Off` نیز editor تا ۶۰ ثانیه لود نشد و save/render تأیید نشد. Elementor page-level clean UI، SiteOrigin Gutenberg Layout Block، Elementor Theme Builder (طبق تصمیم کاربر)، Tab traversal در WebKit و پوشش همهٔ قالب‌ها/builderها ادعا نمی‌شوند. M3 و M4 محلی در دامنهٔ ثبت‌شده تکمیل‌اند؛ lifecycle ZIP با WordPress `Plugin_Upgrader`/`delete_plugins` روی clone QA pass شد و ZIP بیرون از مسیر محلی ارسال/منتشر نشد. NFR-02 فقط در envelope محلی E-15 pass است.
